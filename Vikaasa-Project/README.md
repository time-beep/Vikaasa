# Vikāsa — Plant Health Monitoring System 🌱

**Vikāsa** is a plant-health monitoring project developed by **Team Nexovate** at **Bangalore Institute of Technology**. The project explores combining optical measurements with environmental sensor data to support plant-stress observation.

The team won **third place at Dakshinayasa Darshini**, hosted by Jyoti Institute of Technology.

## How the system is organised

The repository contains the project software, firmware variants, hardware notes, data tools, and supporting documentation. The intended software flow is:

```text
ESP32-C3 firmware → Wi-Fi/HTTP → Flask API → configurable storage → React dashboard
```

This describes the designed software pipeline, not a claim that a complete field deployment has been validated. The API, dashboard, and PlatformIO firmware have implementation and test/build support in the repo; physical calibration and end-to-end device connectivity remain unverified. The ML modules are development scaffolding and are **not** connected to live inference.

## Quick start

### 1. Start the backend

From this `Vikaasa-Project` directory:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e ".[dev]"
# Use the non-persistent local store for development
# PowerShell: $env:STORAGE_BACKEND = "memory"
# macOS/Linux: export STORAGE_BACKEND=memory
python -m Backend.app
```

The API is available at `http://127.0.0.1:5000`. The in-memory store is cleared when the process restarts. Persistent storage requires separately configured Supabase or Firebase credentials and schema setup.

### 2. Start the dashboard

In a second terminal:

```bash
cd Frontend
npm ci
# Optional: copy .env.example to .env.local and set VITE_API_BASE_URL=http://127.0.0.1:5000
npm run dev
```

Vite prints the local dashboard URL, normally `http://localhost:5173`. The `VITE_API_BASE_URL` value is the API base URL **without** `/api`; the provider appends that prefix.

### 3. Build the primary firmware

Install PlatformIO Core, then from this directory:

```bash
cd Firmware/PlatformIO
# Make a local copy and configure Wi-Fi/device settings; never commit secrets.h
cp config/secrets.example.h config/secrets.h
pio run -e glyph_c3-dev
pio run -e glyph_c3
```

Use a Windows file-copy command instead of `cp` in PowerShell. The hardware must match the selected board and pin definitions. Build success does not verify the physical wiring or sensor calibration.

## Test and build commands

From the `Vikaasa-Project` directory:

```bash
STORAGE_BACKEND=memory pytest Backend/tests/ -v
```

From `Frontend/`:

```bash
npm run build
npm run lint
```

From `Firmware/PlatformIO/`:

```bash
pio run -e glyph_c3
pio run -e glyph_c3-dev
```

The repository's GitHub Actions workflow runs backend tests, frontend build/lint, and firmware compile jobs. It does not connect to physical hardware.

## Important measurement and implementation limits

- Raw ADC counts are **not** calibrated reflectance. The `raw_ndvi_estimate` is only a debugging indicator; do not interpret it as a validated plant-health measurement.
- The backend accepts calibrated `ndvi` only when the required calibrated reflectance fields are supplied. It does not infer health labels.
- Alert history is not generated by the current API; `/api/alerts` reports an empty result and `generated: false`.
- The dashboard supports demo data and a Flask API provider. Demo values are simulated and must not be treated as measured data.
- No production authentication is implemented. Do not expose the API publicly as-is.
- Supabase/Firebase production operation needs credentials and the relevant remote schema/database configuration.
- The ML folder has utilities for data validation, preprocessing, features, training interfaces, evaluation, and export; there is no verified trained model or live inference integration in this repo.
- The STL leaf mount is a prototype. Fit, geometry, sensor spacing, calibration, and field performance still need validation.

## Data handling

Use the blank schema in `Data/raw/hardware/vikasa_sensor_data_template.csv` for the backend's 24-field record format. Use [`../Data-Logger/`](../Data-Logger/README.md) for the separate serial-to-Excel collection workflow. Collected files should be saved separately from the blank template, include provenance/labels, and be reviewed before any ML training. Do not commit credentials or unreviewed personal/field readings.
